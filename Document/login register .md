# สรุปขั้นตอนการทำงานของระบบ Login และ Register (Authentication Flow)

เอกสารนี้สรุปขั้นตอนเชิงลึกในการทำงานของระบบเข้าสู่ระบบและลงทะเบียนสมาชิก ทั้งในส่วนของหน้าบ้าน (Frontend) และระบบหลังบ้าน (Backend)

---

## 1. การลงทะเบียน (Registration Flow)

### ฝั่ง Client (LoginPage.jsx)

1. **การกรอกข้อมูล**: ผู้ใช้กรอกข้อมูล (Display Name, Email, Password, Confirm Password)
2. **การตรวจสอบในเบื้องต้น (Validation)**:
   - ตรวจสอบรูปแบบ Email
   - ตรวจสอบความแข็งแรงของรหัสผ่าน (ขั้นต่ำ 8 ตัวอักษร, มีพิมพ์เล็ก-ใหญ่, ตัวเลข และอักขระพิเศษ)
   - ตรวจสอบการยืนยันรหัสผ่าน (Passwords Match)
   - ตรวจสอบการยอมรับเงื่อนไข (Terms & Conditions)
3. **การส่งข้อมูล**: เรียก API `POST /api/auth/register` พร้อมข้อมูลที่กรอก

### ฝั่ง Server (AuthController.register)

1. **การตรวจสอบความปลอดภัย**:
   - ตรวจสอบว่าระบบอนุญาตให้ลงทะเบียนใหม่หรือไม่ (System Settings)
   - ตรวจสอบว่ามีอีเมลนี้ในฐานะข้อมูลแล้วหรือไม่
2. **การรักษาความปลอดภัยรหัสผ่าน**: ใช้ `bcrypt` ในการแฮชรหัสผ่าน (Salt Rounds: 10) ก่อนบันทึก
3. **การกำหนดสิทธิ์ (Role Assignment)**:
   - หากเป็นผู้ใช้คนแรกของระบบ จะถูกตั้งค่าเป็น `admin` โดยอัตโนมัติ
   - ผู้ใช้คนต่อๆ ไปจะเป็น `user`
4. **การบันทึกข้อมูล**: สร้าง User ใหม่ใน MongoDB และสร้างรหัส `uid` สำหรับอ้างอิง
5. **การแจ้งเตือน**: ส่งระบบแจ้งเตือนต้อนรับ (Welcome Notification) ผ่าน Socket.io
6. **การส่งกลับ**: สร้าง **JWT (JSON Web Token)** ที่มีอายุ 30 วัน และส่งข้อมูลผู้ใช้พร้อม Token กลับไปหา Client

---

## 2. การเข้าสู่ระบบแบบปกติ (Manual Login Flow)

### ฝั่ง Client

1. **การส่งข้อมูล**: ส่งอีเมลและรหัสผ่านไปยัง `POST /api/auth/login`
2. **การตรวจสอบ 2FA**: หากได้รับรหัสสถานะว่าต้องการ OTP ระบบจะนำทางไปยังหน้า `/otp-verification`

### ฝั่ง Server (AuthController.login)

1. **การตรวจสอบ Maintenance Mode**: หากระบบอยู่ในโหมดปิดปรับปรุง เฉพาะ Admin เท่านั้นที่จะเข้าระบบได้
2. **การตรวจสอบรหัสผ่าน**: ใช้ `bcrypt.compare` เพื่อเปรียบเทียบรหัสผ่านที่ส่งมากับที่อยู่ในฐานข้อมูล
3. **ระบบ OTP (Two-Factor Authentication)**:
   - หากผู้ใช้เปิด 2FA: ระบบจะสร้างรหัส 6 หลัก ส่งไปทางอีเมล และบันทึกเวลาที่หมดอายุ
   - ผู้ใช้ต้องส่งรหัส OTP มายืนยันในขั้นถัดไปถึงจะได้ Token
4. **การบันทึกประวัติ (Login Tracking)**:
   - บันทึกข้อมูล IP, Browser, OS, อุปกรณ์ และสถานที่ของผู้ใช้ลงใน `LoginHistory`
5. **การส่งกลับ**: ส่ง JWT และข้อมูลโปรไฟล์กลับไปยังหน้าบ้านเพื่อจัดเก็บใน `localStorage`

## 3. การเข้าสู่ระบบด้วย Google (Google Login Flow)

### ขั้นตอนการทำงาน

1. **Frontend**: ใช้ `Firebase Library` เพื่อแสดงหน้าต่าง Popup ของ Google
2. **Frontend -> Server**: หลังจาก Google ยืนยันตัวตนสำเร็จ จะได้ `idToken` มา แล้วส่งต่อไปยัง `/api/auth/google-login-verify`
3. **Server**:
   - ตรวจสอบ `idToken` กับ Firebase Admin SDK
   - หากเป็นผู้ใช้ใหม่: จะสร้างบัญชีใหม่โดยใช้ข้อมูลจากโปรไฟล์ Google (ชื่อ, อีเมล, รูปถ่าย)
   - หากเป็นผู้ใช้เดิม: จะทำการอัปเดตข้อมูลลิงก์กับ Google และอัปเดตรูปโปรไฟล์ให้เป็นปัจจุบัน
4. **Completion**: ออก Token (JWT) ของระบบตัวเองเพื่อให้ผู้ใช้ใช้งานแอปพลิเคชันได้ตามปกติ

---

## 4. ระบบกู้คืนรหัสผ่าน (Forgot Password Flow)

1. **Request**: ผู้ใช้ส่งอีเมลที่ลืมรหัสผ่านในหน้ารวม
2. **Server**: สร้าง `Reset Token` ที่มีความปลอดภัยสูงและมีอายุการใช้งานจำกัด (1 ชั่วโมง)
3. **Email**: ส่งอีเมลที่มีลิงก์พิเศษไปยังอีเมลของผู้ใช้
4. **Reset**: เมื่อผู้ใช้คลิกลิงก์ จะถูกพาไปยังหน้าเปลี่ยนรหัสผ่านใหม่ โดยระบบจะตรวจสอบความถูกต้องของ Token ก่อนอนุญาตให้เปลี่ยน

---

## เทคโนโลยีและความปลอดภัยที่ใช้

- **JWT**: ใช้สำหรับการรักษาความปลอดภัยของ Session (Stateless Auth)
- **Bcrypt**: ใช้เข้ารหัสลับสำหรับรหัสผ่าน
- **Firebase Admin SDK**: ใช้สำหรับยืนยันตัวตนผ่านบุคคลที่สาม (Google)
- **Nodemailer**: ใช้ส่งรหัส OTP และลิงกล์กู้คืนรหัสผ่านทางอีเมล
- **Login Tracking**: ระบบตรวจสอบอุปกรณ์ที่เข้าใช้งานเพื่อความปลอดภัยของผู้ใช้
