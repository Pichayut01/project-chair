# บทที่ 3 การออกแบบและพัฒนาระบบกิจกรรมภายในห้องเรียน

บทนี้นำเสนอรายละเอียดของการออกแบบและพัฒนาระบบกิจกรรมภายในห้องเรียนของโครงการ Project Chair ซึ่งเป็นส่วนหนึ่งของระบบบริหารจัดการห้องเรียนออนไลน์ที่มุ่งเน้นการส่งเสริมปฏิสัมพันธ์ระหว่างผู้สอนและผู้เรียนแบบเวลาจริง ระบบดังกล่าวถูกออกแบบขึ้นเพื่อให้ผู้สอนสามารถสร้างกิจกรรมการเรียนรู้ได้หลายรูปแบบภายในห้องเรียนเดียวกัน เช่น การสุ่มเรียกนักเรียน การตั้งคำถามปลายเปิด การสร้างแบบสำรวจความคิดเห็น การสร้าง Word Cloud การแข่งขันกดปุ่มตอบเร็ว และการแบ่งกลุ่มผู้เรียน โดยกิจกรรมทั้งหมดสามารถดำเนินการและติดตามผลได้แบบทันทีผ่านการสื่อสารระหว่างฝั่งผู้ใช้และฝั่งเซิร์ฟเวอร์

การพัฒนาระบบในส่วนนี้ใช้แนวคิดสถาปัตยกรรมแบบ Client-Server โดยฝั่งผู้ใช้พัฒนาด้วย React สำหรับการแสดงผลและการจัดการสถานะของหน้าจอ ส่วนฝั่งเซิร์ฟเวอร์พัฒนาด้วย Node.js และ Express สำหรับให้บริการข้อมูล จัดเก็บข้อมูล และควบคุมตรรกะการทำงานหลักของระบบ ข้อมูลทั้งหมดจัดเก็บในฐานข้อมูล MongoDB และมีการใช้ Socket.IO เพื่อรองรับการสื่อสารแบบเวลาจริง ซึ่งทำให้ผู้ใช้ทุกคนที่อยู่ในห้องเรียนเดียวกันมองเห็นการเปลี่ยนแปลงของกิจกรรมพร้อมกันโดยไม่ต้องรีเฟรชหน้าเว็บใหม่

## 3.1 ภาพรวมการทำงานของระบบกิจกรรมภายในห้องเรียน

ระบบกิจกรรมภายในห้องเรียนถูกออกแบบให้ทำงานเป็นส่วนหนึ่งของข้อมูลห้องเรียนแต่ละห้อง กล่าวคือ กิจกรรมทั้งหมดจะถูกผูกไว้กับห้องเรียนหนึ่งห้องโดยตรง เมื่อผู้ใช้เข้าสู่หน้าห้องเรียน ระบบจะดึงข้อมูลของห้องเรียนจากฐานข้อมูลขึ้นมาแสดงผล ซึ่งรวมถึงข้อมูลกิจกรรมที่สร้างไว้ก่อนหน้า ข้อมูลผลลัพธ์ของกิจกรรม และข้อมูลการให้คะแนนที่เกี่ยวข้อง จากนั้นระบบจะเชื่อมต่อกับ Socket.IO เพื่อเข้าร่วมห้องสื่อสารของห้องเรียนนั้น ทำให้ทุกการสร้างกิจกรรม การตอบคำถาม การอัปเดตผลลัพธ์ หรือการจบกิจกรรม ถูกส่งต่อไปยังผู้ใช้อื่นในห้องได้ทันที

แนวคิดสำคัญของระบบนี้คือการทำให้กิจกรรมภายในห้องเรียนเป็น “เครื่องมือเรียนรู้แบบมีปฏิสัมพันธ์” ไม่ใช่เพียงองค์ประกอบตกแต่งหน้าจอ ผู้สอนจึงสามารถใช้กิจกรรมเพื่อกระตุ้นความสนใจ ตรวจสอบความเข้าใจ สร้างส่วนร่วม หรือแบ่งกลุ่มสำหรับการทำงานร่วมกันได้จริงระหว่างดำเนินการสอน นอกจากนี้ ระบบยังออกแบบให้รองรับการใช้งานทั้งในมุมมองของผู้สอนและผู้เรียน โดยแต่ละบทบาทจะมองเห็นองค์ประกอบบนหน้าจอแตกต่างกันตามสิทธิ์และหน้าที่ของตน

## 3.2 การออกแบบโครงสร้างข้อมูลของระบบกิจกรรม

ในการออกแบบฐานข้อมูล ผู้พัฒนากำหนดให้ข้อมูลกิจกรรมถูกจัดเก็บไว้ภายในโมเดลห้องเรียน (`Class`) โดยใช้ฟิลด์ `classroomEvents` สำหรับจัดเก็บกิจกรรมที่กำลังใช้งาน และใช้ฟิลด์ `eventHistory` สำหรับเก็บประวัติกิจกรรมที่ถูกลบออกจากรายการหลักแล้ว วิธีการออกแบบดังกล่าวช่วยให้การดึงข้อมูลห้องเรียนสามารถได้ข้อมูลกิจกรรมทั้งหมดในครั้งเดียว ลดความซับซ้อนของการ query และทำให้ฝั่งหน้าจอสามารถสร้างมุมมองของห้องเรียนได้ครบถ้วนภายในการเรียก API เพียงครั้งเดียว

ข้อมูลของกิจกรรมแต่ละรายการประกอบด้วยรหัสกิจกรรม ชื่อกิจกรรม คำอธิบาย ประเภทกิจกรรม ค่ากำหนดของกิจกรรม ผลลัพธ์ที่เกิดขึ้นจริง สถานะของกิจกรรม เวลาเริ่มต้น และเวลาที่เกี่ยวข้องกับการสร้างหรือแก้ไขข้อมูล โดยฟิลด์ที่สำคัญอย่าง `type` ใช้ระบุชนิดของกิจกรรม เช่น `random`, `question`, `poll`, `wordcloud`, `buzz` และ `grouping` ส่วนฟิลด์ `config` ใช้เก็บค่ากำหนดเฉพาะของกิจกรรมแต่ละชนิด เช่น จำนวนคนที่ต้องการสุ่ม คำถามที่ต้องการถาม ตัวเลือกของแบบสำรวจ ระยะเวลาในการตอบ หรือข้อมูลกลุ่มที่ผู้เรียนสามารถเลือกเข้าร่วมได้ ขณะที่ฟิลด์ `results` ใช้เก็บผลลัพธ์ที่เกิดขึ้นจากการมีส่วนร่วมของผู้เรียน เช่น คำตอบที่ส่งเข้ามา ตัวเลือกที่ถูกเลือก หรือรายชื่อของสมาชิกในแต่ละกลุ่ม

นอกจากนี้ ระบบยังออกแบบสถานะของกิจกรรมให้อยู่ในรูปแบบที่สามารถรองรับการใช้งานจริงได้อย่างยืดหยุ่น ได้แก่ สถานะ `draft` สำหรับกิจกรรมที่สร้างไว้แต่ยังไม่เผยแพร่ สถานะ `idle` สำหรับกิจกรรมที่เผยแพร่แล้วและพร้อมใช้งาน สถานะ `active` สำหรับกิจกรรมที่อยู่ระหว่างการทำงาน เช่น การเริ่มการแข่งขันกดปุ่มตอบเร็ว สถานะ `ended` สำหรับกิจกรรมที่สิ้นสุดแล้ว และสถานะ `deleted` สำหรับกิจกรรมที่ถูกย้ายไปเก็บในประวัติ การกำหนดสถานะเช่นนี้ช่วยให้ระบบสามารถควบคุมการแสดงผล การตอบสนองของผู้เรียน และการบันทึกผลได้อย่างเป็นระบบ

## 3.3 การออกแบบกระบวนการสร้างและเผยแพร่กิจกรรม

กระบวนการสร้างกิจกรรมเริ่มต้นจากฝั่งผู้สอน เมื่อผู้สอนอยู่ในหน้าห้องเรียนสามารถเลือกสร้างกิจกรรมจากเมนูที่ระบบจัดเตรียมไว้ โดยในขั้นตอนนี้ระบบเปิดโอกาสให้ผู้สอนกำหนดรายละเอียดของกิจกรรมตามชนิดที่เลือก เช่น หากเป็นกิจกรรมคำถามปลายเปิด ผู้สอนสามารถระบุข้อความคำถาม แนบรูปภาพ และเปิดการจับเวลาได้ หากเป็นแบบสำรวจ ผู้สอนสามารถกำหนดคำถาม ตัวเลือก และกำหนดคะแนนแยกตามตัวเลือกแต่ละข้อได้ หากเป็นการแบ่งกลุ่ม ผู้สอนสามารถระบุชื่อกลุ่ม สีของกลุ่ม และจำนวนสมาชิกสูงสุดที่แต่ละกลุ่มรองรับได้

ระบบรองรับการสร้างกิจกรรมได้ 2 ลักษณะ ได้แก่ การสร้างแล้วเผยแพร่ทันที และการสร้างแบบร่าง (`draft`) สำหรับเก็บไว้ก่อน การสร้างแบบร่างมีประโยชน์ในกรณีที่ผู้สอนต้องการเตรียมกิจกรรมล่วงหน้าและเลือกเวลาเผยแพร่ในภายหลัง เมื่อกิจกรรมถูกบันทึกในสถานะแบบร่าง ผู้เรียนจะยังไม่เห็นกิจกรรมนั้นบนหน้าจอ แต่ผู้สอนยังสามารถกลับมาเปิดดูและกดเผยแพร่ได้ เมื่อผู้สอนกดเผยแพร่ ระบบจะอัปเดตสถานะของกิจกรรมเป็นพร้อมใช้งาน และหากกิจกรรมนั้นมีการเปิดใช้ตัวจับเวลา ระบบจะเริ่มนับเวลาในช่วงที่เผยแพร่จริง ไม่ใช่ช่วงที่สร้างแบบร่างไว้ก่อน

หลังจากผู้สอนสร้างกิจกรรมแล้ว ฝั่งผู้ใช้จะส่งข้อมูลกิจกรรมไปยังเซิร์ฟเวอร์ผ่าน Socket.IO โดยเซิร์ฟเวอร์จะบันทึกข้อมูลลงในฐานข้อมูล จากนั้นจึงกระจายข้อมูลกิจกรรมใหม่ไปยังผู้ใช้ทุกคนที่อยู่ในห้องเรียนเดียวกัน วิธีการดังกล่าวช่วยให้ผู้เรียนเห็นกิจกรรมใหม่ทันทีโดยไม่ต้องรีเฟรชหน้าจอ และช่วยให้กิจกรรมที่เกิดขึ้นระหว่างการเรียนการสอนมีลักษณะต่อเนื่องและเป็นธรรมชาติ

## 3.4 การออกแบบการสื่อสารแบบเวลาจริง

หัวใจสำคัญของระบบกิจกรรมภายในห้องเรียนคือการสื่อสารแบบเวลาจริง ผู้พัฒนาใช้ Socket.IO เป็นกลไกหลักในการเชื่อมโยงการทำงานระหว่างผู้สอน ผู้เรียน และเซิร์ฟเวอร์ โดยเมื่อผู้ใช้เข้าสู่ห้องเรียน ระบบจะเชื่อมต่อ socket และเข้าร่วมห้องของห้องเรียนนั้นโดยอัตโนมัติ จากนั้นทุกคำสั่งสำคัญ เช่น การเพิ่มกิจกรรม การเปลี่ยนสถานะกิจกรรม การส่งคำตอบ และการลบกิจกรรม จะถูกส่งผ่าน socket event เฉพาะทางไปยังเซิร์ฟเวอร์

ฝั่งเซิร์ฟเวอร์ทำหน้าที่รับคำสั่ง ตรวจสอบเงื่อนไขที่เกี่ยวข้อง เช่น ตรวจสอบว่ากิจกรรมยังเปิดรับคำตอบอยู่หรือไม่ ตรวจสอบว่าหมดเวลาหรือยัง และทำการอัปเดตข้อมูลในฐานข้อมูล หลังจากนั้นเซิร์ฟเวอร์จะกระจายผลลัพธ์กลับไปยังผู้ใช้ทุกคนในห้องเดียวกันผ่าน event ที่สัมพันธ์กัน เช่น เมื่อมีกิจกรรมใหม่ถูกสร้าง ระบบจะส่ง event แจ้งว่ามีกิจกรรมใหม่ เมื่อมีคำตอบเข้ามา ระบบจะส่ง event อัปเดตผลลัพธ์ และเมื่อกิจกรรมถูกจบ ระบบจะส่ง event เพื่อเปลี่ยนสถานะของกิจกรรมให้ทุกคนเห็นพร้อมกัน

ลักษณะการออกแบบเช่นนี้ช่วยให้หน้าจอของผู้ใช้ทุกคนมีข้อมูลสอดคล้องกันในเวลาใกล้เคียงกันมากที่สุด ลดโอกาสเกิดข้อมูลไม่ตรงกัน และส่งเสริมประสบการณ์ใช้งานในห้องเรียนที่มีความต่อเนื่อง ทั้งในมุมมองของการสอนและการเรียน

## 3.5 การออกแบบกิจกรรมแต่ละประเภท

กิจกรรมแบบสุ่มเรียกนักเรียน (`random`) ถูกออกแบบขึ้นเพื่อช่วยให้ผู้สอนสามารถเลือกผู้เรียนจากรายชื่อที่กำลังนั่งอยู่ในห้องได้อย่างรวดเร็ว ระบบจะดึงข้อมูลจากรายชื่อนักเรียนที่ถูกกำหนดที่นั่งไว้แล้ว จากนั้นสุ่มตามจำนวนที่ผู้สอนระบุ และแสดงผลผ่านหน้าจอด้วยลักษณะภาพเคลื่อนไหวก่อนเฉลยผลจริง การออกแบบดังกล่าวมีเป้าหมายเพื่อเพิ่มความน่าสนใจและลดความซ้ำซากของกระบวนการเรียกผู้เรียนตอบคำถาม

กิจกรรมคำถามปลายเปิด (`question`) ถูกออกแบบให้เหมาะกับการตรวจสอบความเข้าใจหรือการสะท้อนความคิดเห็นของผู้เรียน ผู้สอนสามารถกำหนดคำถาม แนบรูปประกอบ และเปิดเวลาจำกัดในการตอบได้ ฝั่งผู้เรียนจะเห็นพื้นที่สำหรับพิมพ์คำตอบ ขณะที่ฝั่งผู้สอนสามารถดูคำตอบทั้งหมดที่ส่งเข้ามาแบบสด และเปิดดูคำตอบรายบุคคลได้ในรูปแบบหน้าต่างแยก การออกแบบนี้ช่วยให้ผู้สอนติดตามความคิดของผู้เรียนได้สะดวกและใช้ข้อมูลดังกล่าวประกอบการสอนในช่วงเวลาถัดไป

กิจกรรมแบบสำรวจความคิดเห็น (`poll`) ถูกออกแบบเพื่อรองรับคำถามที่มีตัวเลือกหลายข้อ ผู้สอนสามารถตั้งคำถาม เพิ่มตัวเลือกได้อย่างยืดหยุ่น และในกรณีที่ต้องการใช้กิจกรรมดังกล่าวเป็นส่วนหนึ่งของการประเมิน ก็สามารถกำหนดคะแนนให้แต่ละตัวเลือกได้แยกจากกัน ฝั่งผู้เรียนจะมองเห็นตัวเลือกในรูปแบบปุ่มสำหรับกดตอบ ส่วนฝั่งผู้สอนจะเห็นผลลัพธ์ในลักษณะกราฟแท่งหรือแถบเปอร์เซ็นต์แบบเวลาจริง การออกแบบนี้ช่วยให้ผู้สอนสามารถใช้กิจกรรมแบบ poll ได้ทั้งเพื่อเก็บความคิดเห็นอย่างรวดเร็วและเพื่อใช้เป็นกิจกรรมที่มีการให้คะแนน

กิจกรรม Word Cloud (`wordcloud`) ถูกออกแบบขึ้นเพื่อรวบรวมคำตอบสั้น ๆ จากผู้เรียน และนำมาสร้างภาพรวมเชิงภาพของคำที่ปรากฏบ่อย โดยผู้เรียนสามารถส่งคำตอบสั้นเพียงครั้งเดียว และผลลัพธ์จะถูกนำไปแสดงในรูปแบบเมฆคำบนหน้าจอของห้องเรียน นอกจากนี้ ผู้สอนยังสามารถเปิดมุมมองแบบนำเสนอแยกต่างหากผ่าน route สำหรับ presentation เพื่อใช้ฉายขึ้นจอในห้องเรียนได้โดยเฉพาะ การออกแบบนี้เหมาะสำหรับกิจกรรมระดมความคิด การสะท้อนความรู้สึก หรือการสรุปประเด็นสำคัญอย่างรวดเร็ว

กิจกรรมกดปุ่มตอบเร็ว (`buzz`) ถูกออกแบบให้มีลักษณะเป็นเกมหรือการแข่งขัน ผู้สอนสามารถเริ่มการนับถอยหลังได้จากหน้าควบคุม เมื่อเวลานับถอยหลังสิ้นสุด ผู้เรียนจึงจะสามารถกดปุ่มเพื่อตอบสนองได้ ระบบจะบันทึกลำดับและเวลาที่ผู้เรียนแต่ละคนกดเข้ามา จากนั้นแสดงผลฝั่งผู้สอนในลักษณะลำดับผู้ชนะ การออกแบบนี้มุ่งเน้นการสร้างบรรยากาศการเรียนรู้ที่สนุกและกระตุ้นการตอบสนองของผู้เรียน

กิจกรรมแบ่งกลุ่ม (`grouping`) ถูกออกแบบให้ผู้เรียนเลือกเข้ากลุ่มด้วยตนเอง โดยผู้สอนสามารถกำหนดชื่อกลุ่ม สีประจำกลุ่ม และจำนวนสมาชิกสูงสุดในแต่ละกลุ่มได้ ระบบจะแสดงจำนวนสมาชิกที่เข้าร่วมแต่ละกลุ่มแบบเวลาจริง พร้อมทั้งแสดงสถานะว่ากลุ่มใดเต็มแล้ว นอกจากแสดงในรูปแบบ event card ภายในหน้าห้องเรียนแล้ว ระบบยังส่งข้อมูลกลุ่มไปยังแชตของห้องเรียนในรูปแบบข้อความพิเศษ เพื่อให้ผู้เรียนสามารถเลือกเข้ากลุ่มผ่านแชตได้อีกช่องทางหนึ่ง การออกแบบนี้ช่วยให้การแบ่งกลุ่มทำได้สะดวกขึ้นและเหมาะกับกิจกรรม collaborative learning

## 3.6 การออกแบบตัวจับเวลาและการควบคุมสิทธิ์การตอบ

ระบบตัวจับเวลาในกิจกรรมถูกนำมาใช้กับกิจกรรมคำถามปลายเปิดและแบบสำรวจความคิดเห็นเป็นหลัก ผู้สอนสามารถกำหนดระยะเวลาได้เป็นนาทีและวินาที เมื่อเริ่มกิจกรรม ระบบจะบันทึกเวลาที่เริ่มต้นและเวลาที่สิ้นสุดไว้ในค่ากำหนดของกิจกรรม ฝั่งผู้เรียนจะเห็นเวลาคงเหลือผ่านแถบแสดงสถานะบนหน้าจอ ขณะที่ฝั่งเซิร์ฟเวอร์ทำหน้าที่ตรวจสอบเวลาอีกชั้นหนึ่งทุกครั้งที่มีการส่งคำตอบเข้ามา หากเซิร์ฟเวอร์พบว่าหมดเวลาแล้ว จะปฏิเสธคำตอบนั้นทันที

แนวทางนี้ช่วยป้องกันปัญหาที่อาจเกิดจากการพึ่งพาการตรวจสอบเฉพาะฝั่งหน้าจอเพียงอย่างเดียว เพราะแม้ว่าหน้าจอของผู้เรียนจะถูกแก้ไขหรือเกิดความล่าช้าในการแสดงผล เซิร์ฟเวอร์ยังคงเป็นผู้ตัดสินขั้นสุดท้ายว่าคำตอบนั้นส่งทันเวลาหรือไม่ จึงช่วยให้กิจกรรมที่มีข้อกำหนดด้านเวลาเกิดความเป็นธรรมมากขึ้น

## 3.7 การออกแบบกระบวนการคิดคะแนน

ระบบกิจกรรมภายในห้องเรียนรองรับการให้คะแนนได้ 2 รูปแบบหลัก รูปแบบแรกคือการให้คะแนนทันทีที่ผู้เรียนตอบ ซึ่งใช้งานกับกิจกรรมแบบสำรวจความคิดเห็นที่กำหนดคะแนนรายตัวเลือกไว้ เมื่อผู้เรียนส่งคำตอบ เซิร์ฟเวอร์จะตรวจสอบว่าตัวเลือกนั้นมีค่าคะแนนอย่างไร หากเป็นการบวกคะแนนก็จะเพิ่มคะแนนให้ผู้เรียนทันที หากเป็นการลบคะแนนก็จะหักคะแนนตามค่าที่กำหนด และจะส่งข้อมูลการอัปเดตคะแนนกลับไปยังผู้ใช้ทุกคนที่อยู่ในห้องพร้อมทั้งสร้างการแจ้งเตือนให้ผู้เรียนที่ได้รับผลจากคะแนนดังกล่าว

รูปแบบที่สองคือการให้คะแนนภายหลังจากผู้สอนกดจบกิจกรรม หรือ `End & Score` ซึ่งใช้กับกิจกรรมที่ต้องการให้ผู้สอนตัดสินใจจบช่วงกิจกรรมก่อน เช่น คำถามปลายเปิด Word Cloud การสุ่มเรียกนักเรียน และการแข่งขันกดปุ่มตอบเร็ว ในขั้นตอนนี้ ฝั่งผู้ใช้จะประมวลผลรายชื่อผู้ที่ควรได้รับคะแนนตามหลักเกณฑ์ของกิจกรรมแต่ละประเภท แล้วส่งข้อมูลคะแนนที่อัปเดตไปบันทึกยังเซิร์ฟเวอร์ วิธีการนี้เหมาะกับกิจกรรมที่ต้องการให้ผู้สอนมีอำนาจควบคุมช่วงเวลาของการประเมินมากกว่าการให้คะแนนโดยอัตโนมัติทันที

คะแนนทั้งหมดของผู้เรียนถูกจัดเก็บไว้ในฟิลด์ `studentScores` ของห้องเรียน ซึ่งจัดเก็บในลักษณะ key-value ตามรหัสผู้เรียนและหมวดคะแนนที่เกี่ยวข้อง วิธีการจัดเก็บเช่นนี้ช่วยให้ระบบสามารถนำคะแนนไปแสดงต่อในหน้าสรุป หน้าประวัติ หรือใช้ร่วมกับฟังก์ชันอื่นของห้องเรียนได้สะดวก

## 3.8 การออกแบบการเก็บประวัติกิจกรรมและการย้อนดูข้อมูล

เพื่อให้ระบบสามารถติดตามข้อมูลกิจกรรมย้อนหลังได้ ผู้พัฒนาได้ออกแบบกลไกสำหรับเก็บประวัติของกิจกรรมที่ถูกลบออกจากรายการหลัก เมื่อผู้สอนลบกิจกรรม ระบบจะไม่ลบข้อมูลทิ้งโดยสมบูรณ์ แต่จะคัดลอกข้อมูลเดิมไปเก็บใน `eventHistory` พร้อมระบุเวลาที่ลบและเปลี่ยนสถานะเป็น `deleted` จากนั้นจึงนำกิจกรรมนั้นออกจากรายการกิจกรรมที่ใช้งานอยู่ แนวทางนี้ช่วยให้ผู้ดูแลระบบหรือผู้สอนยังสามารถกลับมาดูข้อมูลเดิมได้ในภายหลัง

ในส่วนของการแสดงผล ระบบมีหน้าประวัติกิจกรรมที่รวมทั้งกิจกรรมที่ยังคงอยู่และกิจกรรมที่ถูกลบแล้วเข้าด้วยกัน ผู้ใช้ในบทบาทที่ได้รับสิทธิ์สามารถกรองข้อมูลตามประเภทกิจกรรม สถานะ และคำค้นหาได้ อีกทั้งยังสามารถใช้ข้อมูลดังกล่าวเพื่อวิเคราะห์แนวโน้มการมีส่วนร่วมของผู้เรียนหรือการกระจายคะแนนจากกิจกรรมต่าง ๆ ได้อีกด้วย การออกแบบนี้ช่วยให้ระบบไม่ได้หยุดอยู่เพียงการใช้งานระหว่างเรียน แต่ยังสามารถนำข้อมูลไปใช้ในเชิงวิเคราะห์และติดตามผลภายหลังได้

## 3.9 การออกแบบการนำเสนอผลลัพธ์แบบแยกหน้าจอ

กิจกรรม Word Cloud มีความสามารถพิเศษเพิ่มเติมคือการเปิดหน้าจอนำเสนอแยกออกจากหน้าห้องเรียนหลัก ผู้สอนสามารถกดเปิด presentation mode เพื่อให้ระบบสร้างหน้าจอเฉพาะสำหรับการแสดงผลเมฆคำแบบเต็มรูปแบบ หน้าจอนี้จะดึงข้อมูลกิจกรรมจากเซิร์ฟเวอร์และเชื่อมต่อกับ Socket.IO เช่นเดียวกับหน้าหลัก จึงสามารถอัปเดตคำที่ผู้เรียนส่งเข้ามาได้แบบเวลาจริง การออกแบบดังกล่าวเหมาะกับการใช้งานในห้องเรียนจริงที่ผู้สอนต้องการฉายผลลัพธ์ขึ้นจอโปรเจกเตอร์หรือจอส่วนกลางให้ผู้เรียนเห็นพร้อมกัน

## 3.10 การสรุปผลการออกแบบ

จากการออกแบบและพัฒนาระบบกิจกรรมภายในห้องเรียน พบว่าระบบดังกล่าวสามารถทำหน้าที่เป็นกลไกสนับสนุนการเรียนการสอนแบบมีปฏิสัมพันธ์ได้อย่างครบถ้วน โดยอาศัยการประสานงานระหว่างโครงสร้างข้อมูลของห้องเรียน การสื่อสารแบบเวลาจริงผ่าน Socket.IO และการประมวลผลเชิงตรรกะทั้งฝั่งผู้ใช้และฝั่งเซิร์ฟเวอร์ การออกแบบให้กิจกรรมเป็นส่วนหนึ่งของห้องเรียนโดยตรงช่วยให้การจัดการข้อมูลทำได้ง่ายและเชื่อมโยงกับฟังก์ชันอื่นของระบบได้ดี ขณะเดียวกัน การแบ่งชนิดของกิจกรรมออกเป็นหลายรูปแบบช่วยให้ผู้สอนเลือกใช้เครื่องมือให้เหมาะสมกับบริบทการเรียนรู้ที่แตกต่างกัน

กล่าวโดยสรุป ระบบกิจกรรมภายในห้องเรียนที่พัฒนาขึ้นนี้มีความเหมาะสมต่อการนำไปใช้เป็นองค์ประกอบสำคัญของห้องเรียนอัจฉริยะ เนื่องจากรองรับทั้งการสร้างกิจกรรม การโต้ตอบแบบเวลาจริง การให้คะแนน การจำกัดเวลา การแบ่งกลุ่ม และการติดตามผลย้อนหลัง ซึ่งล้วนเป็นองค์ประกอบที่ช่วยส่งเสริมการมีส่วนร่วมของผู้เรียนและเพิ่มประสิทธิภาพในการจัดการเรียนการสอนของผู้สอนในสภาพแวดล้อมดิจิทัล
